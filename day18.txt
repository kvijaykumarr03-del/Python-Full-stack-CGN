 Introduction to Triggers
A trigger is a special type of stored program that automatically executes (fires) in response to a specific event — INSERT, UPDATE, or DELETE — occurring on a specified table. Unlike a stored procedure, a trigger is never called directly; the database engine invokes it automatically when the triggering event happens.
General Syntax
DELIMITER //
 
CREATE TRIGGER trigger_name
{BEFORE | AFTER} {INSERT | UPDATE | DELETE}
ON table_name
FOR EACH ROW
BEGIN
	-- trigger logic
	-- use NEW.column_name for inserted/updated values
	-- use OLD.column_name for deleted/previous values
END //
 
DELIMITER ;
Keyword
Meaning
BEFORE
Trigger fires before the triggering event is applied to the table. Often used for validation.
AFTER
Trigger fires after the triggering event has been applied. Often used for auditing/logging.
NEW
Refers to the new row values. Available in INSERT and UPDATE triggers.
OLD
Refers to the row values before the change. Available in UPDATE and DELETE triggers.
FOR EACH ROW
Required in MySQL — the trigger body runs once per affected row.

Trigger Examples
1. BEFORE INSERT (Validation)
Question:
Do not allow employees with salary less than ₹20,000.
Trigger SQL:
DELIMITER //
 
CREATE TRIGGER trg_before_insert_salary
BEFORE INSERT
ON Employees
FOR EACH ROW
BEGIN
	IF NEW.salary < 20000 THEN
    	SIGNAL SQLSTATE '45000'
    	SET MESSAGE_TEXT='Salary cannot be less than 20000';
	END IF;
END//
 
DELIMITER ;
Test:
INSERT INTO Employees
VALUES(106,'Arjun','IT',15000,2,'Delhi');
Output:
ERROR 1644 (45000):
Salary cannot be less than 20000

Question:
Store inserted employee details in the audit table.

ON Employees

QUESTION & ANSWER BANK
Question
Answer
Q1. What is a stored procedure?
A precompiled, named set of SQL statements stored in the database that can be executed using the CALL statement. It can accept parameters and contain procedural logic such as variables, conditions, and loops.
Q2. What is the default parameter mode if none is specified in CREATE PROCEDURE?
IN. If no mode is written before a parameter name, MySQL treats it as an IN parameter.
Q3. What is the difference between IN, OUT, and INOUT parameters?
IN passes a value into the procedure only (read-only inside). OUT is set inside the procedure and returned to the caller (initial value ignored). INOUT passes a value in, allows it to be modified, and returns the updated value to the caller.
Q4. Why do we use DELIMITER // before creating a procedure or trigger?
Because the procedure/trigger body itself contains semicolons to separate statements. Changing the delimiter to // (or similar) tells the client to treat the entire block as one statement, ending only at //, so the internal semicolons don't terminate the CREATE statement early.
Q5. How do you call a stored procedure that has an OUT parameter?
Declare a session variable (e.g., @result), pass it in the CALL, then SELECT the variable afterward: CALL proc(@result); SELECT @result;
Q6. How do you permanently remove a stored procedure?
Use DROP PROCEDURE [IF EXISTS] procedure_name;
Q7. What is a trigger in SQL?
A database object that automatically executes a defined block of SQL in response to an INSERT, UPDATE, or DELETE event on a specified table, without being called explicitly.
Q8. What is the difference between a BEFORE trigger and an AFTER trigger?
A BEFORE trigger fires before the change is applied to the table and can validate/modify the incoming row (commonly used for validation). An AFTER trigger fires once the change has been committed and is commonly used for auditing/logging, since it cannot alter the row anymore.
Q9. What do NEW and OLD refer to in a trigger?
NEW refers to the new/incoming row values (available in INSERT and UPDATE triggers). OLD refers to the row's values before the change (available in UPDATE and DELETE triggers). INSERT triggers have no OLD; DELETE triggers have no NEW.
Q10. Can a trigger call a stored procedure or return a value to the caller?
A trigger can call certain stored procedures/functions internally in some databases, but it can never return a value directly to the statement that fired it (unlike a stored procedure called with CALL).
Q11. Why use FOR EACH ROW in a MySQL trigger?
MySQL only supports row-level triggers, so FOR EACH ROW is mandatory — it specifies that the trigger body executes once for every row affected by the INSERT, UPDATE, or DELETE statement.
Q12. How would you reject an invalid INSERT using a trigger?
Create a BEFORE INSERT trigger that checks the NEW row values with an IF condition and raises a custom error using SIGNAL SQLSTATE '45000' SET MESSAGE_TEXT = 'error message'; this aborts the insert.
Q13. Give a real-world example of using a trigger for auditing.
An AFTER UPDATE trigger on an employees table that inserts the emp_id, old_salary, new_salary, and timestamp into a salary_history table every time a salary changes.
Q14. Give a real-world example of using a trigger for validation.
A BEFORE INSERT trigger on a products table that rejects any row where quantity is negative or price is less than or equal to zero, using SIGNAL to raise an error.
Q15. How do you remove a trigger from a database?
Use DROP TRIGGER [IF EXISTS] trigger_name; This removes only the trigger definition, not the table or its data.
Q16. What is the main advantage of stored procedures over sending raw SQL from an application?
Reduced network traffic (single CALL instead of multiple statements), improved performance through precompilation/caching, centralized and reusable business logic, and finer-grained security via EXECUTE privileges instead of direct table access.
Q17. Can a single table have multiple triggers for the same event (e.g., two AFTER INSERT triggers)?
MySQL allows multiple triggers for the same event and timing from version 5.7.2 onward, executed in the order they were created (or as specified with FOLLOWS/PRECEDES); many other databases also support this with similar ordering rules.
Q18. What happens to existing data in a table when its trigger is dropped?
Nothing — DROP TRIGGER only removes the automatic firing logic. All existing rows and data in the table remain completely untouched.
